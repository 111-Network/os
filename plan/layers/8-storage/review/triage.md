## Forks the reports leave open, or where two reports disagree

| ids | ruling |
|---|---|
| S5 vs I22 (a store that does not fit twice at a migrating update) | Both, in this order. The release manifest names the store schema versions a release writes (additive). An update that migrates a store which does not fit above the floor, or cannot be copied inside the probation window, is refused by release N−1's updater (`409 insufficient_space`, the bytes needed named) and shown on the Storage and update pages. A human may accept "update without a rollback copy" (a consent whose text says: if this release fails, messaging stays closed until the next update); then, and only then, the migration runs without a copy and a revert leaves the store closed, as I22 describes. Copy and migration finish before the daemon reports health (`EXTEND_TIMEOUT_USEC`). Seconds per GiB on an SD card are a build measurement. Listed in §22 for the owner. |
| D1 + D2 vs I3 (how kiwix registers) | D2's shape: no tenth service. `panelId` is a `ServiceId` or a `ComponentId`; a `child` panel's id is its component's id, it has no `bundle`, it is enabled while its component is enabled, its health is the component's port, and it is framed from Storage → Datasets ("Open encyclopedia", named in §15.4). `Component.adapter` is optional in the parser, nullable in the contract and in the UI row (null = a server component). The declaration: `program` per target in `[payload.targets.<t>]` for a tarball's inner path; `{root}/state/kiwix/library.xml` (no new placeholder); `[run] start = "on_demand"`: enable stops after install, `resume_enabled` skips it, and claim, pre-bind and start happen at the first session mint; `health = "listen"`; an adapterless component's state and log directory is `state/<id>/` (in the §13.8 ring); "remove files" removes it. Stop is a named new route, `POST /api/v1/bridge/components/{id}/stop`, valid for `on_demand` components only. §21 L5 (5), §21 L6 and §16.6 carry the whole additive set; a node111 unit test parses the embedded `kiwix.toml` and `panels/kiwix.toml`. |
| I5 vs D29 (which role bit says "this hub has a catalogue") | A new bit, not a wider bit 5: `ROLE_DATASETS`, the next free role bit after Layer 9's, set while `origin.datasets` is consented (the drafter checks the width in `N/fabric/sealer.rs` and L2 A17 and names the bit). Bit 5 keeps its Layer 7 meaning, so a Layer 7 member's behaviour is unchanged. The attribution GET runs only against a hub whose signed announce carries the bit; the "last answer" state is dropped. D29 then reads: "`origin.components` changes no role bit; `origin.datasets` sets `ROLE_DATASETS`". The `datasets_serve` consent text says the bit is public to every card holder. G15 asserts no request to a hub without the bit. |
| D14 (kiwix-serve idle stop: a deviation from F8 A) | Accepted, by the Pi-floor rule: kiwix-serve stops on the existing pass when no request reached the proxy for 30 passes; the next panel open starts it. §19's column is renamed, the panel listener gets its own column, C16 is corrected, §22 lists the deviation for the owner. |
