# Layer 9 gap-fill 3 - adopt vs build for playbook rules (cel, serde_json_path, a closed predicate enum)

Scout report, 2026-11-02. Question (critic 06 section 5 G3): `01-observe-diagnose.md` section 3.3 invents an `expect:` mini-language for playbook
checks; do adoptable rule engines beat it, given the Pi floor, Layer 0's locked entry format and rule 1 (data never executes)? Read-only: no cargo, no
build, nothing run; binary-size figures are estimates from crates.io metadata, not links. Network: raw.githubusercontent.com and the crates.io API
answered; docs.rs, en.wikipedia.org, ieeexplore, researchgate and docs.stackstorm.com did not. Licences below were read from upstream LICENSE files
unless marked.

## 1. Summary

- **Pick: a closed predicate enum in our own code (grammar v1, about twelve predicates and three combinators), zero new dependency.** The playbook's
  machine part is a fenced TOML block (the `toml` and `serde` crates are already in `node111`, `Cargo.toml` dependency list), evaluated by a pure
  function over typed facts that `111d` already holds. `cel` and `serde_json_path` each need a JSON-shaped fact document built per evaluation, which
  is the real vocabulary anyway, and then add a parser plus 8 to 23 crates the frozen dependency set does not contain.
- **`cel` 0.15.0 is the right power but the wrong weight and stability.** MIT (LICENSE read), non-Turing complete, side-effect-free, terminating by
  the language definition (`cel-spec langdef.md:12-13`); but 8 releases in four months (0.13.0 2026-03-12 to 0.15.0 2026-10-06, a new `Env` API in the README beside
  the older `Program::compile` of `lib.rs`; how breaking is unverified), an ANTLR runtime (`antlr4rust`, BSD-3-Clause per crates.io) with 8 direct dependencies, `regex` and `chrono` + `chrono-tz` on by default,
  and no evaluation cost budget found in the sources read (only a parser recursion cap of 96, `parser.rs:153`). None of `regex`, `chrono`, `nom`,
  `lazy_static`, `uuid`, `parking_lot` is in `1-bootstrap/Cargo.lock` (319 entries) or `3-intelligence/Cargo.lock` (109).
- **`serde_json_path` 0.7.2 is lighter but answers the wrong question.** RFC 9535 selects nodes; a predicate is "the node list is non-empty". It has no
  literal-substring test (only `match`/`search`, regex), no counters over a window, no universal quantifier. Last release 2025-02-03 (21 months old),
  `inventory` runs constructor code before `main` (`inventory/README.md:93-98`).
- **The shape every prior art converges on is the same: declarative trigger + criteria over a CLOSED operator list + an action from a registry.** What
  the permissive ones got wrong is the action side: StackStorm templates event data into action parameters (`{{ trigger.payload_parameter_1 }}`,
  `rules.rst:41`; the sample rule runs `echo "{{trigger.body}}"` through `core.local`), Salt renders Jinja per event into a reaction
  (`reactor.py:52-80`), Icinga's event command is a command line with macros (`03-monitoring-basics.md:2634-2637`). Ours must close the action set too
  (the typed kinds of `02-change-validate.md` section 3.2, not a command, no templating).
- **Layer 0 can carry it with a small amendment, no new frontmatter field:** category `playbook`, folder `playbooks/`, the machine part in one fenced
  `toml` block under `### Checks` inside the existing `## Details` heading (the frontmatter subset allows one nested level only, so predicates cannot
  live there). `build.py` is Python 3.11+, so stdlib `tomllib` lints the block with no new Python dependency.
- **Fail closed by construction:** `schema = 1` in the block, `deny_unknown_fields`, an internally tagged serde enum with no catch-all variant; an unknown
  predicate, unknown field or `schema` above the node's maximum rejects the WHOLE playbook (shown as "needs a newer release"), never skips a check.

## 3. Findings that change the plan

### 3.1 What the checks have to say (from the other reports)

01 section 3.3 names two checks (`children.rnsd == backoff`; `tail contains 'address already in use'`); 02 section 3.2 names the verify steps (service
Running for 30 s; `/health` 200 and the row leaves `degraded`; `rnstatus` lists the interface up); the brief for this scout adds counters over N events,
file existence and exit codes. Every one of these is a **typed read of state `111d` computes anyway** (`ChildState {Running, Backoff, Degraded,
Stopped}`, `supervise.rs:416-421`; the closed `reason_code` strings, `services/mod.rs:264,641`; the sanitized log tails, `services/log.rs:16-18`;
`/health`, `health.rs:24-41`). None needs arithmetic across facts, string building or iteration over data the playbook author supplies. That is the
argument for an enum: the vocabulary is a list of facts, not a language.

### 3.2 The closed grammar, v1 (a design for the lead, not a spec)

Facts are read through one trait implemented by `111d` (and by a struct in tests, so a golden case is a pure function call, 02 F12). Predicates, each a
serde variant with named, typed, bounded fields:

1. `service_state {id, is}` - `is` in the `ChildState` set; `id` in the 9 fixed service ids (`00-code-seams.md` row `services/mod.rs:80-105`).
2. `service_reason {id, is}` - `is` in the closed `reason_code` vocabulary (`openapi.yaml:614`); the loader checks it against the compiled list.
3. `restarts_at_least {id, n, within_events}` - counter over the last `within_events` (at most 64) supervisor transitions of `id`; clock-free (02 F2, F10).
4. `incident_count_at_least {n}` - the deduplicated `count` of the open incident (01 section 3.2).
5. `exit_is {id, code | signal}` - the last recorded exit (needs the `ExitStatus` that `supervise.rs:972` discards today, 00 seams row).
6. `health_is {is}` - `ok | degraded | down`.
7. `file_exists {root, rel}` - `root` in `{state, run, data}`; `rel` matches `^[a-z0-9._-]+(/[a-z0-9._-]+)*$`, no `..`; a `metadata()` call, never a read.
8. `log_contains {id, literal}` - a literal of at most 64 bytes, searched in the last 100 lines or 8 KiB of the sanitized tail; no regex (log text is
   attacker-influenced; a literal cannot backtrack and cannot be made to match everything).
9. `disk_free_below {percent}` - the fabric statvfs result (00 seams row `fabric/mod.rs:59,319-326`).
10. `unclean_exit {}` - the run marker of 01 section 3.2.
11. `component_enabled {id, is}` - consent state; `can_run_here` is already a registry field.
12. `release_at_least {calver}` - applicability of a fix to a release range (the scope check 04 finding 9 wants in `111d`, not the model).

Combinators: `all`, `any`, `not`; depth at most 3, at most 16 leaves, whole block at most 2 KiB (parse-time bounds, so evaluation is O(leaves) and
trivially terminating). `any_service_state {is}` and similar quantifiers are added when a playbook needs one, as a grammar bump (3.6).

**Limits, stated honestly:** (a) a new fact is a code change and so a release, which is the intended gate under rule 1 but means a hub-drafted playbook
cannot test something the running release does not expose; (b) no arithmetic between facts (`a > b`), no regex, no time windows in seconds, no list
comprehension; (c) every predicate is one more case for the golden-test suite; (d) quantifiers over sets need explicit variants. A reader who wants
cel's `all()/exists()` gets them one named variant at a time. In exchange: the set of facts a playbook reads is statically enumerable (a lint prints
it, a consent UI can show it), and the grammar is a JSON-Schema `oneOf` that llama.cpp turns into a GBNF grammar (`01` section 3.3, `grammars/README.md:143-147`),
so a hub's model can draft a syntactically valid playbook; it cannot do that for a free-form CEL string.

### 3.3 Comparison on the criteria that matter

| Criterion | Closed enum | `cel` 0.15.0 | `serde_json_path` 0.7.2 |
|---|---|---|---|
| New crates in `111d` | 0 | about 11-13 (min), about 23 (default) | about 8 (11 with `regex`) |
| Runtime power | exactly the listed facts | arithmetic, strings, `all/exists/map/filter`, timestamps, `matches` | node selection, comparisons, `match/search/length/count/value` |
| Side effects / termination | by construction | by language definition (`langdef.md:12-13`); user-defined functions are host code | by construction (a query language) |
| Resource bound | parse-time caps (depth, leaves, bytes) | parser recursion 96 (`parser.rs:153`); no evaluation cost cap found; a macro over a long list is linear in the list (`langdef.md:904`) | none found; size of the fact document |
| Needs a fact document | no (lazy typed reads) | yes (a context of variables) | yes (a `serde_json::Value`) |
| Static "which facts?" lint | trivial (variants) | walk the AST (`ExpressionReferences`, `lib.rs`) | walk the query |
| Model-draftable under a grammar | yes (JSON Schema) | needs a CEL GBNF; string syntax errors | needs a JSONPath GBNF |
| Stability risk | ours | high: pre-1.0, eight releases in four months | low churn, low activity |
| Portability of the language | none (ours) | CEL is a published spec, a conformance suite exists in the repo (`Cargo.toml` members) | RFC 9535 |

The fact document is the hidden cost of both libraries: it must be materialised (service rows, tails, counters) each evaluation, then kept in sync with
a schema that is the same closed vocabulary as the enum, only without compile-time checking.

### 3.4 Prior art: what it got right about keeping checks declarative and the action set closed

- **StackStorm** separates `trigger`, `criteria` (a field path, a `type`, a `pattern`) and `action` (`rules.rst:26-60`), with the criteria operators a
  registry (`operators.py:415-449`) that rejects an unknown one with "Invalid operator" (`operators.py:38-43`): fail closed on the check side. Got wrong
  for us: `action.parameters` are Jinja over event payload, and `core.local` runs a shell string.
- **Salt reactor** maps an event tag glob to a reaction file (`reactor.py:82-113`); the reaction is a rendered state/runner/wheel/local call. Event
  data flows into the rendered text; nothing closes the call set.
- **Nagios and Icinga** make the trigger a state machine edge (soft/hard state, recovery) and keep the retry count in the monitor, not the handler; the
  handler is a command. Take: the trigger is a state transition with a count (our incident fingerprint plus `count`); leave the command.
- **Ansible handlers**: declared apart from tasks, notified by name, run once per play (`playbooks_handlers.rst:79`). Take: one named action per
  cause, deduplicated; the model may only name a cause id (01 section 3.3).
- **Kubernetes probes**: four mechanisms, no scripting beyond `exec`, and thresholds as numbers; `failureThreshold * periodSeconds` is the whole
  "within N" logic. Take: counts, not expressions, for windows. K8s also splits liveness, readiness and startup, which maps to our trigger, check
  and verify.
- **MAPE-K**: Monitor = registry, supervisor and fabric events in `111d` (01 section 3.1); Analyse = playbook `match` plus checks (T0), the model only
  choosing among cause ids (T1); Plan = the typed action and its pure `plan()` dry-run (02 F12); Execute = the applier; Knowledge = shipped
  playbooks, the incident ring and the ledger (02 fork E). The playbook is the Knowledge in "over knowledge"; nothing here needs more than that.

### 3.5 The action side: closed by sharing the applier's types

A cause's `action` is deserialised into the SAME Rust enum the applier accepts (`applier.rs:85-105`: four applied kinds, two one-shots, four refused
names; unknown = `409 unsupported_action` before any write, `:20-22`), plus two playbook-only cases that cannot change state: `advise` (text shown to
the human) and `escalate` (submit a hub task, `tools.rs` `task.submit`). Parameters are literals validated by the same serde types; the single
non-literal is the reference `"@subject"`, replaced by the incident's service id (a closed set), so one playbook can serve every degraded child. No
`{{ }}`, no environment, no event text ever reaches a parameter (the Jinja path in StackStorm and Salt is exactly the data-becomes-code channel rule 1
forbids). Because the loader and the applier share one type, a playbook cannot name an action the engine would refuse, and widening the vocabulary
(`bridge.edge.pause`, 04 E1) widens both at once, with the applier's probe and revert attached.

### 3.6 Layer 0 amendment and grammar pinning

**Layer 0 amendment (locked spec, `0-knowledge/README.md`; the lead brings it to the owner as part of fork 4 of 01):**
- `category: playbook` joins the enum (F05) with folder `playbooks/`; one generated `llms.txt` there; `status` applies (candidate, testing, proven; **proven**
  = it healed a real incident, logged in `### Field log`, which fits 01's reading of the rubric).
- **No 13th frontmatter field.** Fields used: `title`, `category`, `status`, `summary` (descriptive only, as today), `tags`, `platforms`, `last_verified`,
  `sources`, `relations` (`depends_on` the project or component it repairs, `runs_on` the devices it applies to; the scope check costs no new code, 04
  finding 9). `upstream` and `license` stay inapplicable (omitted, F04): playbooks are first-party.
- **Filename** `repair-<subject>-<reason>.md` (subject = service or layer slug, reason = the `reason_code` with `_` as `-`); a new N-rule requires the
  block's `[match]` to agree with the filename and with the closed vocabulary. Recipes stay `install-<project>-on-<device>.md` (N03 untouched).
- **Body:** the six fixed H2 headings are unchanged (B02). A playbook uses H3s under `## Details`: `### Symptom`, `### Checks` (the fenced `toml` block),
  `### Causes` (prose, one line per cause id), `### Verify`, `### Undo`; `## Evidence` keeps `### Smoke test` and `### Field log`. New lint: the block
  parses with `tomllib`, `schema` is an integer within the supported range, every field is known, vocabulary values (service ids, reason codes) resolve,
  limits hold (2 KiB, 16 leaves, depth 3). The Rust loader enforces the same rules again at load (the node trusts its own parse, not CI). Token budget:
  body at most 2000 (warning-only, like the others), so the retrieval ritual of about 3.5k tokens still fits one playbook plus its refs (`README.md:37`).
- **Content trust:** the block is data inside a code fence (permitted); it contains no command and no URL.
- **Where it lives at runtime:** shipped in the release payload (`share/kb/`, immutable, 02 F5), read by `111d`; a node overlay (02 tier A vs 04's
  "no overlay in v1", critic conflict 4) is outside this gap.

**Pinning:**

```toml
schema = 1                               # grammar version this block is written in; an integer, never a range
[match]  layer = "transport"  reason = "stack_down"  subject = "rnsd"
[[check]]  id = "c1"  all = [ { p = "service_state", id = "rnsd", is = "backoff" },
                              { p = "log_contains", id = "rnsd", literal = "address already in use" } ]
[[cause]]  id = "port_busy"  when = ["c1"]  action = { kind = "service.restart", service_id = "@subject" }
           verify = { p = "service_state", id = "rnsd", is = "running" }
[[cause]]  id = "unknown"  when = []  action = { kind = "escalate", task = "diagnose" }
```

Rules: (1) the evaluator has `MAX_SCHEMA` (a const) and refuses `schema > MAX_SCHEMA` and `schema < 1`; (2) each predicate carries `SINCE` and is refused
inside a block whose `schema` is lower (keeps the block honest about what it needs); (3) `deny_unknown_fields` on every table and an internally tagged
enum `p` without a fallback variant: any unknown predicate, field, service id or reason code rejects the whole playbook, which then shows as "unsupported
grammar N, needs release X" in the Repairs page and never partially runs; (4) additions are additive within a major only; changing the meaning of an
existing predicate is a new name, not a new meaning; (5) a runtime absence is not an error: `service_state` of a component not installed on this node
evaluates false, while an id outside the compiled vocabulary is a load error; (6) a fixture per playbook (facts in, matched check ids out) lives in
the repo for CI, not in the payload (the cases are 02's "golden cases"); a changed grammar re-runs every fixture. Because playbooks ship in the same signed
release as the evaluator, version skew can only arise from an overlay or a shared KB frame, which is exactly where failing closed matters.

## 4. Recommendation (fork)

**Fork G3 - how playbook rules are expressed**
- A. **Closed predicate enum, grammar v1, in `111d`; TOML block in a Layer 0 `playbook` entry** (the pick). Cost: about 200 lines of Rust plus a
  fact trait, a Layer 0 amendment (category, folder, lint, one H3 vocabulary), a fixture suite. Binary and RSS change: nothing measurable.
- B. `cel` behind a cargo feature, default off, hubs only. Defensible later if the corpus shows playbooks fighting the enum; needs a pinned
  exact version (`=0.15.0`), `default-features = false` (drop `regex`, `chrono`), a cost cap we write ourselves, a dependency-policy sign-off row
  (`1-bootstrap/TASKS.md` policy: set frozen) and a size measurement first. It also splits semantics between hubs and phones: a playbook valid on a
  hub is inert on a Pi, which defeats shipping one KB.
- C. `serde_json_path`: reject (3.3).
- D. Keep 01's `expect:` strings: reject; it needs a hand-written parser, which the structured block removes entirely.
- **Pick A.** It meets the Pi floor at zero, keeps rule 1 literal (the check language cannot name a command, and the action set is the applier's type),
  and the grammar doubles as the model's drafting schema. Revisit B at the first playbook that needs an expression the enum cannot give.
