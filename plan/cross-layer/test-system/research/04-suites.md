# 04 - Crate and UI suites as cross-layer evidence (scout: suites)

Read-only survey, 2026-11-11. Nothing was executed; counts come from `grep -cE '^\s*#\[(tokio::)?test'` (Rust) and `grep -cE '^\s*(it|test)(\.each)?\('` (UI) per file, so `it.each` rows and macro-generated tests count once.

## Summary

Five test populations exist. **node111** integration tests: 42 entries in `1-bootstrap/crates/node111/tests` (35 `*.rs` files plus README.md, `common/`, `fake_python/`, `fixtures/`, `fake_rnodeconf`, 2 `fake_*.py`), 446 test fns; plus 566 unit tests in `node111/src`. **mesh111** 58 integration tests (9 files), **id111** 56 (3 files), **agent111** 121 (8 files + `common/`), **UI** 1286 `it` over 45 `*.test.ts` (the 48 entries also hold the generated `contract.gen.ts`, 3965 lines, and `helpers/`, `tapes/`). The real cross-layer seams are few and uneven. Strong: (a) the OpenAPI contract is digested into `4-interface/ui/test/contract.gen.ts` by `gen-sse.mjs`, and BOTH sides validate against it: the UI mock/adapter tests, and five node111 Rust files that `read_to_string` that `.ts` file and parse the JSON out of it (api_v1_messages/bridge/transport, bridge_core, dashboard_auth); freshness is gated by `gen.test.ts` running `gen-sse.mjs --check`. (b) 11 SSE tapes recorded from a real daemon by `4-interface/verify/smoke.sh` are replayed through the real UI parser/mappers (`tapes.test.ts`). (c) `attest-transport-ids.json` is produced by id111 and replayed by node111 (twice). (d) The id111 and mesh111 frozen vectors are live gates with drift checks, and an independent Python `crosscheck.py` per set. Weak: the agent111 <-> node111 seam is two independent hand-written fakes (agent111's stub `111d` returns hand-typed JSON that is never validated against the contract; node111's stub agent is hand-typed too); no test runs the real agent binary against the real daemon outside the netns `smoke.sh --three-node`. Root, python3 and sh are assumed by many tests; only two tests skip themselves visibly. Failure reporting is plain `cargo test` / `vitest` text: named test fn, no JSON, no log path, no per-seam tag.

## Weak points for an agent localising a cross-layer failure

1. **No seam tag.** A failing `api_v1_messages::...` is named by test fn only; nothing says "daemon vs contract" versus "daemon vs mesh111". `contract.gen.ts` mismatches show as `assert_schema("Message", ...)` panics in each Rust file's own copy of the validator.
2. **Two copies of the contract validator** (UI TypeScript and Rust ports in 5 node111 files, `re_match` etc.) can diverge from each other: the UI treats `oneOf` as any-branch; the Rust ports do the same by stated intent only.
3. **Stale digest risk on the Rust side**: Rust tests trust whatever `contract.gen.ts` is on disk; only the vitest suite (`gen.test.ts`) detects staleness, so a Rust-only run after an `openapi.yaml` edit validates against the old contract.
4. **agent111 fake is unchecked** against the contract and has three divergent copies; the agent <-> daemon seam has no real-to-real test in any `cargo test`.
5. **Tapes** only cover L4/L5 streams and need root+netns to refresh; L6 tapes exist but nothing consumes them; L7 has none.
6. **Wall of output**: node111 is 446 tests in 35 binaries, ~38.7k lines of test code (`wc -l`); `cargo test` prints one line per test, no JSON; fail context is a panic message plus a backtrace only with `RUST_BACKTRACE`. The `forward` suite is ~3 min. Compile of node111 tests is heavy (14 GB shared target dir, HANDOFF:52; at most two cargo builds at once on the 12 GB box).
7. **Visible-skip vs silent-pass**: the root guard in `api_v1_devices.rs:1506` passes silently; the python3 skip is gated by env. A summary reporting "446 passed" includes skipped bodies.
8. **Root dependence cuts both ways**: root hides permission failures (`0o500`, `0o000`) and causes the 8 known red tests. A root-only sandbox cannot distinguish them without the TASKS note.
9. **Frozen-vector files cannot be edited to fix a red test** (README rule: fix the code); an agent must know this, and `UPDATE_GOLDEN=1` / `SMOKE_TAPES=1` / `--ignored` generators are the opposite (rewrite on request).
10. **Python helpers**: `fake_lxmf_sidecar.py`, `fake_deltachat_rpc.py`, `stub-ntfy.py` are spawned by tests; a missing or slow `python3 -I` surfaces as a timeout or spawn error inside the adapter test rather than as a named environment failure.
