# 03 - Layer 6 and Layer 7 verify harnesses (scout l6-l7-harness)

Read-only survey of `6-transport/verify/` and `7-relay/verify/` at the current tree. Nothing was run. Counts are from boards or counted from source (method given).

## Summary

Layer 6 has five real gate scripts (G1 `bridge.sh`, G3 `lxmf.sh`, G4 `spine.sh`, G5 `devices.sh`, G7 `zero-weight.sh`), all green on 2026-10-23 and re-run after fix waves (`6-transport/TASKS.md:80`: G1 130 -> 132, G3 147, G4 128/129, G5 98/99; 177-248 s each). Layer 7 has only one real script mode: `carrier.sh --smoke` (row P1, committed `a553cf3`). G7-extended `idle.sh`, G8 `presence.sh`, G9 `forward.sh`, G10 `carrier.sh` (default), G11 `tls.sh`, G12 `origin.sh` are T0 stubs that print `<G> SKIPPED: not built yet (T0 stub)` and exit 0; rows V1-V6 are all `⬜` (`7-relay/TASKS.md:93,107-112`). There is NO aggregate entry point: no `check.sh`, `.github/workflows/ci.yml` or other script calls any `6-transport/verify/*` or `7-relay/verify/*` file (grep over `*.sh`/`*.yml`: only a git-grep exclusion at `ci.yml:130-132`); the netns gates are "the lead's" by design (spec 7 section 15 CI mapping). All share one convention (`6-transport/verify/lib.sh`): lines `ok:` / `FAIL:` / `note:`, final line `<GATE> GREEN` or `<GATE>: N FAIL`, `SKIPPED` plus exit 0 unless `REQUIRE_<GATE>=1`. There is no machine-readable result (no JSON/JUnit); the only structured artifacts are `egress-log.py` JSON output and `inner.result` (`FAILS=n`) in a scratch dir. Layer-joining is real but narrow: L6 gates drive real `111 daemon`s (L1) through `/api/v1` (L4 contract) with stub adapters or real rnsd/LXMF helper, and mesh111 (L5) store tests; L7 verify joins only L1 carrier code to a Python stub server.

## Cross-cutting weak points for an agent localising a seam failure

1. No umbrella runner and no machine-readable summary: each script ends with `G<n>: N ok, M FAIL in Ts` (L6 netns gates) or `G<n> GREEN` / `G<n>: N FAIL` (stderr); a driver must parse stdout+stderr together and treat `SKIPPED` as a distinct non-pass state (stdout, exit 0).
2. SKIPPED masks FAIL: spine.sh and devices.sh print cargo FAIL lines first and may then `skip_or_fail` on a missing venv/PyPI and exit 0 (bridge.sh likewise after a failed build with no binary). A wrapper must scan for `^FAIL:` even when exit is 0.
3. FAIL is on stderr in `lib.sh::fail` but stdout in the redefined `ok/fail` of the four netns gates; the closing `finish` line is stderr on failure.
4. Locating a failure: assertion text is the key (grep `^FAIL:`); HTTP gates append status + 300-byte body; the matching log is in the kept scratch dir (`/tmp/111-g1.*`, `111-g3.*`, `111-spine.*`, `111-devices.*`; paths printed once by `note: scratch kept at`). Scratch is kept on failure only; nothing deletes it later; no per-phase log files except cargo logs.
5. Runtime cost: ~3-5 min per gate, no way to run one phase (no filter flag); the inner namespace run emits everything through `tee`.
6. Environment gates: unprivileged userns+netns (all), mount-ns overmount (G5), strace (G3), PyPI (G3/G4/G5, 3 separate caches), GitHub download (G5 Madmail), git tag `checkpoint-layer-5` (G1) and `checkpoint-layer-6` (G9, absent), a running daemon (G7). `REQUIRE_<G>=1` flips each to FAIL.
7. Stubs are honest only if the seam hook is: G1 depends on a debug-only `scenario` module; G5 on fake `/dev`/`/sys`; G3 on an inject-free tap (asserts no `+ ` line).
8. Docs drift: counts differ between board rows (G3 136 vs 147), baseline-listeners comment on 4242, L7 lib port/addr names are "T0 defaults".
