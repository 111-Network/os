# 02 - Layer 4 running-system harnesses (scout l4-harness)

Read-only scout, 2026-11-11. Nothing was executed; every count below is from the source (method stated). Paths are relative to `/home/user/os`.

## Summary

Layer 4 owns the only real end-to-end harnesses in the tree. `4-interface/verify/smoke.sh` (1,666 lines) has two modes. Single-node mode runs a real `111 daemon` plus a real `111-agent` (L3) and a stub model inside `unshare -rnpf`. It covers the L4 HTTP contract, the L1 `/api/status` seam and pairing from a non-loopback source. Three-node mode (`--three-node`) runs four real daemons in veth/bridge netns and drives L2 (identity, announce, epoch), L5 (fabric, custody, tcp-lan, proposals) and the L3 tool path. It also touches L6/L7 edges only through the Meshtastic stub. `panel-lint.sh` is a third netns harness (curl matrix plus headless Chrome over CDP) for the L5 hosted-panel origin guard. `check-budget.mjs` is a bundle size gate. The contract chain is: `api/openapi.yaml` -> `ui/scripts/gen-sse.mjs` (and `openapi-typescript`) -> committed `types.gen.ts`, `sse.gen.ts` and `test/contract.gen.ts`. That digest is read by vitest (UI side) and by five Rust test files (daemon side), and CI regenerates and diffs it. There is NO check that compares the daemon's router to the yaml: `api/README.md:3-5` says the Rust DTOs will get `utoipa` later and CI will then diff. All harnesses use one idiom: `ok:` / `FAIL:` / `note:` lines, with a final GREEN/RED line and exit 0/1. Their common weaknesses for an agent are: the namespace run needs user namespaces, `ip` and `nsenter`; output is a long linear log with no machine-readable result; the scratch dir is deleted on success; and the outer script can report GREEN after a silent mid-run abort (see S1).

## Common conventions (smoke.sh, panel-lint.sh)

- Counters: `ok()` / `fail()` / `note()` (`smoke.sh:81-89`, `panel-lint.sh:54-62`) print `ok: <desc>` / `FAIL: <desc>` / `note: <desc>`. Phases print `\n== <title>  (t+<s>s)` (`smoke.sh:92`).
- `t DESC CONDITION` evals the condition string and on failure prints `FAIL: <desc>  [HTTP <status>: <first 300 bytes of body>]` (`smoke.sh:134-136`). Every failing check is therefore named by its description plus the last HTTP status and body snippet, but not by a stable id or number. Checks are not numbered.
- JSON helpers `jb/jf/jqs` refuse empty input because `jq -e` exits 0 on no input (`smoke.sh:114-130`). Every "nothing left / nothing changed" check carries a positive control (`smoke.sh:29-33`).
- Final lines (`smoke.sh:1662`, `1666`): `SMOKE GREEN - <N> checks ok, 0 FAIL, in <s>s` exit 0, else `SMOKE RED - <N> FAIL line(s) in <s>s` exit 1. For panel-lint: `PANEL-LINT GREEN - ...` / `PANEL-LINT RED - ...` (`panel-lint.sh:578`, `581`). The usage error is exit 2 (`smoke.sh:1428`).
- The outer script runs the inner part as `unshare --user --map-root-user --net --pid --fork --kill-child --mount-proc <env --default-signal> bash smoke.sh --inner|--inner3 | tee inner.log || true` (`smoke.sh:1631-1633`, `1649-1651`). The outer counts `^FAIL:` lines in `inner.log` (`:1653`). The inner exit code is discarded by `|| true`.
- Scratch dir: `mktemp -d -t 111-smoke.XXXXXX` under `$TMPDIR`. It is deleted on success and kept on any FAIL or with `SMOKE_KEEP=1`, printing `note: scratch kept at $WORK (daemon.log, agent/, http/)` (`smoke.sh:1446-1453`). panel-lint uses `111-panel-lint.XXXXXX` and `PANEL_LINT_KEEP=1` (`panel-lint.sh:447-454`).
- No machine-readable result exists. The only structured files are `inner.result` (`FAILS=<n>`) and the SSE tapes. Logs go to `$WORK/logs/*.log` (pnpm, cargo, identity), `$WORK/inner.log` (the whole run), and per node `$ROOT/daemon.log`, `agent/111-agent.log`, `meshtastic/meshmud.log`.

  - **False GREEN on a silent abort.** The inner function runs under `set -euo pipefail` and its EXIT trap always writes `inner.result` (`:179-190`). The outer only checks that the file contains `FAILS=` (`:1654`) and then adds the count of `FAIL:` lines. A `set -e` abort between checks prints no `FAIL:` line, but the trap still writes the result file, so the outer reports GREEN. The only guard against a crash is the missing result file. Not run; found by reading (`:1654-1657`).
  - The first `exit 1` after a daemon that never answers kills the remaining 80+ checks without naming them.
  - No per-check ids, so an agent has to grep the description text.
  - Polling loops (30-60 s) hide the cause in the timeout; only some print a diag.
  - The harness writes to `ui/dist` during the run (the probe file); an aborted run could leave `smoke-probe-*.txt` (removed by trap `:180`).
  - It needs a working `unshare -rn` and `ip`; it cannot run in a container without user namespaces.

## S6. UI contract and tape tests (vitest, `4-interface/ui/test`, 46 `*.test.ts` files; 1,286 `it(`/`test(` lines by grep)

- **Run:** `pnpm --dir 4-interface/ui test` (`vitest run`), or `pnpm exec vitest run test/tapes.test.ts`. No daemon, no network, no root. Output: vitest's own format (failing test names with the message). A CI job runs it inside `1-bootstrap/scripts/check.sh` (`:169-176`), which prints `UI checks SKIPPED` and calls `skipped ui` when pnpm is missing (an agent must read the SKIPPED list).
- **Tapes (`tapes.test.ts`, 139 lines; `test/tapes/`, 11 `.sse` files + README):** each tape is a byte-for-byte recording written by smoke.sh. The gate: the SSE parser gives the same frames whole, in 7-byte and in 1-byte chunks; every frame's event name is in `x-sse-events` (events or chat) and its JSON payload validates against its schema, including required keys; ids are strictly increasing; the real `connectEvents` client drops no frame; the chat client yields every frame in order and ends with exactly one terminal. Failure messages name the tape and frame (`events.sse frame #0 (reset): ...`, `tapes.test.ts:35`). The test deliberately fails if fewer than 3 events and 3 chat tapes exist ("deleting them would turn this gate off"). Joins: L4 daemon (recorded) -> UI parser. `kindOf` forces the `events*`/`chat*` name prefix.
- **Contract tests:**
  - `gen.test.ts`: runs `node scripts/gen-sse.mjs --check` (fails if `sse.gen.ts` or `contract.gen.ts` is stale), and re-runs `openapi-typescript` into a temp dir and requires it to equal committed `types.gen.ts` byte-for-byte (skipped silently if the binary is absent, `gen.test.ts:34`). It pins runtime enum tuples (`SERVICE_IDS`, `PROBLEM_CODES`, L7 enums...) to the yaml enums.
  - `http.test.ts`: builds the HTTP adapter with a fake `fetch`; for every operation in the digest except `events` it asserts method, path regex, required query, no undeclared query keys, request body valid against the request schema, JSON content-type on writes (`http.test.ts:440-480`). A guard test requires the call table to equal the digest's operation set (`:440-441`), so a new yaml operation without an adapter call fails.

## S7. openapi.yaml drift: what is compared with what

`4-interface/api/openapi.yaml` (2,065 lines, 79 `operationId`s, 67 path keys by `grep -c`) is the hand-maintained source (`api/README.md:3-5`: "interim source of truth until the Rust DTOs carry utoipa annotations").

1. **yaml -> generated TS (committed copies).** `pnpm gen:types` = `openapi-typescript ../api/openapi.yaml -o src/lib/api/types.gen.ts && node scripts/gen-sse.mjs` (`package.json`). `gen-sse.mjs` (630 lines, own YAML-subset reader) writes `src/lib/api/sse.gen.ts` and `test/contract.gen.ts` (schemas + every operation). Checks: `gen-sse.mjs --check` prints `stale: <file>` plus `generated files are out of date with api/openapi.yaml; run pnpm gen:types`, exit 1 (`:603-628`); the vitest `gen.test.ts` calls it; and CI step "Contract drift" runs `pnpm gen:types` then `git diff --exit-code -- 4-interface/ui/src/lib/api` (`.github/workflows/ci.yml:124-128`). Note the CI diff covers only `src/lib/api`, not `test/contract.gen.ts` (the vitest `--check` covers that).
2. **contract digest -> UI.** `http.test.ts` (adapter vs every operation), the tapes gate (recorded daemon frames vs `x-sse-events` schemas), mock and fixture tests (S6).
3. **contract digest -> daemon (Rust tests, no spawned binary).** Five Rust test files read `4-interface/ui/test/contract.gen.ts` by relative path and parse the JSON after a marker string: `api_v1_messages.rs` (`assert_schema`, every L5 route's 2xx body and problem plus SSE `message/contact/fabric` frames; it also greps the yaml line for `Message.reason_code` and requires `not_enrolled (`, `cancelled (` and the `hub_not_yours (...sent after...REJECT_UNKNOWN_DEST` text, `:1979-2000`), `api_v1_transport.rs` and `api_v1_bridge.rs` (L6 routes; port of `validate.ts`), `bridge_core.rs`, and `dashboard_auth.rs` (walks every contract operation and requires the agent bearer to be refused on every write; an `UNROUTED` list of 9 operationIds, `dashboard_auth.rs:1409-1419`, names contract operations with no daemon route yet: flashDevice and eight L7 ones). They run with `cargo test --workspace` (`.github/workflows/ci.yml:77`). `api_v1_status_services.rs` pins `/status` and services by hand against the yaml (comment only; no digest read), and `api_v1_relay.rs`, `api_v1_devices.rs`, `api_v1_panels.rs`, `api_v1_meshtastic.rs` use no schema validator (grep count of `assert_schema`/`fn contract` = 0).
4. **Not checked anywhere (gap).** No test enumerates the daemon's actual axum routes and compares them with the yaml paths; a daemon route missing from the yaml, or a yaml path with no route, is caught only per operation by tests that call it (and the `UNROUTED` list in `dashboard_auth.rs`). `smoke.sh` calls only a subset of the operations (not counted; no L6/L7 route appears in it). The CI regeneration from Rust (`utoipa`) described in `api/README.md` does not exist yet.
