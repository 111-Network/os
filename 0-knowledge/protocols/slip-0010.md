Hardened-only Ed25519 HD derivation standard that pairs with BIP-39 seeds.

## What it is

SLIP-0010 is the SatoshiLabs standard for hierarchical deterministic key
derivation on Ed25519, status Final. Derivation is hardened-only, using
HMAC-SHA512 keyed with the literal string ed25519 seed. It is the
convergent wallet path for backing up an Ed25519 identity from a seed
phrase: Trezor, Ledger, Stellar, Cardano, and Solana ecosystems all
implement it.

## Use when

- An Ed25519 private key must be derived from a [[bip-39]] mnemonic so a
  node identity restores from words alone.
- The derivation must run anywhere, including Cat 1; the construction is
  HMAC-SHA512 only, no elliptic-curve math in the derivation itself.
- A spec-level standard with many independent implementations is needed;
  for protocols, that replaces repo-activity gates.

## Do NOT use when

- Interop with Cardano-style BIP32-Ed25519 is expected; the two schemes
  are incompatible and restore different keys from the same words and
  path, so one must be pinned explicitly with test vectors.
- Soft (non-hardened) derivation is wanted; Ed25519 here is
  hardened-only by design.
- The backup format lacks a versioned descriptor; a bare mnemonic does
  not record which derivation produced the key.

## Details

Research confirmed in 2026 that no single blessed ed25519-from-BIP39
standard exists: SLIP-0010 and the Cardano BIP32-Ed25519 variant produce
different keys from the same seed and path. The identity layer pins
SLIP-0010 at its own paths, using the key half of the HMAC output as the
RFC 8032 private seed and discarding the chain code, with fixed hardened
indices for signing and encryption keys. The spec itself has no audit
concept; implementations have been audited many times over inside
wallets.

## Evidence

### Alternatives considered

- BIP32-Ed25519 (Cardano variant) — incompatible soft-derivation scheme;
  rejected to keep restore unambiguous.
- Full BIP-32/44 wallet trees — solve address rotation and coin-type
  separation that a one-key-per-node identity does not have.
- 2026-10-12 — desk research sweep; entered at candidate under the
  protocol adaptation: stable spec plus multiple independent
  implementations.
