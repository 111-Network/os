`plan/layers/6-transport/review/` (`bridge.md`, `carriers.md`, `integration.md`, `triage.md`, `recheck.md`). Contract: `4-interface/api/openapi.yaml`
(additive). Tasks that share a file never run in parallel; the Files column is the ownership record. Rust in `1-bootstrap/crates/node111` is Layer 1's
crate (Layer 6 owns the `bridge/`, `transport/`, `devices/` modules and `meshtastic/client.rs` there, D15-style); `mesh111` store/fabric changes are
additive (schema V3, D25 F1). Model per task: Rust → **opus**; UI, docs, KB, Python → **sonnet**; tiny transforms → haiku; integrated review →
fable. Lead reviews every task against its check before commit. Wave order follows D25 F5 (bridge-first): the store, contract and seams first, then
the bridge core and the Meshtastic client, then LXMF, app peers and the device core, then verification. Owner-gated items are closed by D26.

`panel-lint.sh` together; Linux hygiene (`AGENTS.md`): nothing of ours stays running after a check.
