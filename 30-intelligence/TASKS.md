## Pinned contracts (bind every task; additive-only after T0)

**Crate:** workspace at `os/30-intelligence/`; single crate `crates/agent111` (package `agent111`, `[[bin]] name = "111-agent"`). Host target for dev; musl-static x86_64/aarch64 is the release shape (`cargo check --target x86_64-unknown-linux-musl` must stay green).

**Dependency policy:** only the deps scaffolded in T0's `Cargo.toml`; `Cargo.lock` committed; new deps require reviewer sign-off recorded in the task's status note. Approved set: tokio · axum · serde/serde_json · anyhow · time · ureq (plain HTTP only, `default-features = false` + `json` — no TLS: endpoints are loopback/private fabric, encryption is Layer 5's job) · tokio-stream (reviewer sign-off T0: axum SSE responses need a `Stream`; standard minimal companion) · tempfile (dev-only). Test servers use std `TcpListener` helpers in `tests/common/` — no HTTP-mock crates.

**Module stubs** (created in T0, tasks fill them): `config` · `health` · `model` · `kb` · `tools` · `chat` · `tasks` · `events` · `status` · `store` · `http`.

**Cross-module APIs** (frozen at T0; signatures may gain plumbing, not change semantics):
- `config::Config::load(env, args) -> Config` — `port` (default 11182) · `model_base` (default `http://127.0.0.1:11181`) · `model_id` (default `qwen3-4b`) · `kb_dir` (default `/var/lib/111/kb/current`) · `state_dir` (default `/var/lib/111/agent`) · `category` · `daemon_health_url` (default `http://127.0.0.1:11180/health`) · `opencode_path` (default `opencode`) · `node_id: Option<String>` · *(Layer 5, A1)* `daemon_api_url` (default `http://127.0.0.1:11180/api/v1`, loopback IP literal only) · `daemon_token: Option<DaemonToken>` (`AGENT111_DAEMON_TOKEN`, process environment only, redacted `Debug`) (env `AGENT111_NODE_ID` / `--node-id`; Layer 2 NodeId hex handed down by 111d, stamps proposals) · `lan bool` (default false).
- `model::Client { base, model_id }` · `Client::reachable() -> bool` · `Client::chat_stream(req, on_delta) -> Reply` where `Reply = { text, tool_calls: Vec<ToolCall> }` — OpenAI-compatible `/chat/completions`, streaming.
- `kb::Kb::open(dir) -> Kb` (absent dir ⇒ `Kb::absent()`, never panic) · `Kb::index_prompt() -> String` (root llms.txt digest for the system prompt) · `Kb::grep(name) -> Vec<String>` (filenames only, `_meta/` excluded) · `Kb::read_one(path) -> Option<String>`.
- `events::Journal::append(kind, detail)` — JSONL, capacity-trimmed (1 MiB FIFO); `Journal::subscribe() -> broadcast receiver` for SSE.
- `store::Store { state_dir }` — `conversation(id) -> append/load JSONL` · `save_proposal(Proposal) -> id` · `save_task(Task) -> id`; every state write goes through `store`.

**HTTP contract** (axum, bind `127.0.0.1:11182`; LAN bind only with `lan true` + startup warning; Host allowlist `127.0.0.1`/`localhost` any port; all GETs GET-only):
- `GET /health` → `{schema:1, status:"ok"|"degraded"|"error", components:{model:bool, kb:bool, state_dir:bool}}`; 200 for `ok`|`degraded` (process alive — supervision must not restart the agent over a dead hub or absent KB), 503 only for `error` (state_dir unusable).
- `GET /v1/agent/status` → `{schema:1, state:"local"|"offloaded"|"unavailable", model:{base, reachable:bool, id}, kb:{present:bool, entries:null|int}, conversations:int, tasks_open:int, uptime_sec, version}`.
- `POST /v1/chat` → body `{conversation_id:null|str, message:str, stream:bool(default true)}`. `stream:true` ⇒ SSE `data:` events, each a JSON object: `{"type":"delta","text":"…"}` per text delta · `{"type":"tool_call","name":"…"}` when a tool runs · `{"type":"done","conversation_id":"…","reply":"…","tool_trace":[{"name","ok"}]}` final, then `data: [DONE]` · `{"type":"error","error":"…"}` on mid-stream failure; if the model is known-unreachable up front ⇒ HTTP 503 `{schema:1,error}` before any stream. `stream:false` ⇒ JSON `{schema:1, conversation_id, reply, tool_trace:[…]}`.
- `GET /v1/chat/history?conversation_id=…` → `{schema:1, conversation_id, messages:[OpenAI message objects in order]}`; unknown id ⇒ 200 with empty `messages`; missing param ⇒ 400. (111d's relay serves Layer 4 from this — the UI never talks to 11182 directly.)
- `GET /v1/agent/events` → SSE stream of `{schema:1, seq, ts, kind, detail}` (replay last 50 + live).
- `POST /v1/agent/task` → body `{kind:"diagnose"|"propose"|"patch", refs:[str], note:null|str}` → 202 `{task_id}`; `patch` without a working opencode ⇒ 409 `{schema:1, error:"needs hub"}`.
- Errors: `{schema:1, error:str}` with honest codes (503 model unavailable, 400 bad body, 409 needs hub).

**Tools (fixed set — no shell, ever):** `kb.read{query}` · `health.read{}` (own components + daemon_health_url probe) · `logs.read{n}` (journal tail) · `proposal.write{title, body}` · `task.submit{kind, refs, note}` · *(Layer 5, A1 — appended in this order)* `messages.read{peer?, since_seq?, limit}` · `messages.send{to, text}` (writes a proposal of kind `message`, never sends) · `contacts.read{}` · `fabric.read{}` · `nearby.read{}` (untrusted block). Tool protocol = OpenAI tool-calling; loop bounded at 4 tool rounds per chat turn. · *(Layer 6, D27 — appended in this order, 10 → 17; see README "Appendix — Layer 6 tools")* `bridge.read{network?, conv?, since_seq?, limit}` (foreign names, ids and bodies inside one labelled untrusted block) · `bridge.propose_edge{from, to, why}` (proposal kind `bridge_edge`) · `devices.read{id?}` · `transport.read{}` · `device.identify{device_id, why}` (proposal kind `device`, one `identify` action) · `device.propose{why, actions}` (kind `device`; the closed DEV §3 vocabulary + `identify`, `service.restart`) · `service.restart{service_id, why}` (kind `device`); `messages.send{to | targets: [{network, conv}], text}` (kind `bridge_message` with targets). Every tool issues GETs only; the bearer is refused on every non-GET by 111d (D26 #2).

**Honesty rules (bind every task):** distinct states (`local|offloaded|unavailable`), never silent · KB absent ⇒ chat says knowledge is absent, never invents project facts · `patch` without opencode ⇒ `needs hub` · model base guard: loopback always allowed; RFC1918/ULA/link-local always allowed (that **is** the hub offload case — a 2A node offloads while still binding loopback); any public/WAN host refused at startup, no override · `lan` flag controls endpoint binding only, never the model guard.

**State layout** (`state_dir`, created 0700): `conversations/<id>.jsonl` · `proposals/<id>.json` `{schema:1, id, node_id:null|str, task_id:null|str, kind, title, body, created_at}` · `tasks/<id>.json` `{schema:1, id, kind, refs, note, state:"running"|"done"|"failed"|"refused", proposal_id:null|str, created_at, finished_at}` · `events.jsonl`.

**Cross-layer wiring (built layers, minimal):** Layer 1 — `111d` spawns `111-agent` and `llama-server` as supervised children through its existing `spawn_child(ChildSpec)` (the rnsd pattern) when the binaries exist in `current/bin/`; child env carries category, KB dir (`<root>/current/share/kb`), state dir (`<root>/agent`), env file (`<etc>/agent.env`), node id; `/api/status` gains an additive `intelligence` object. Layer 2 — node id only (public NodeId hex) flows to the agent; **no private key material ever reaches the agent**; proposal *signing* is deferred to Layer 9's PR packaging (which can call id111 as root-of-trust holder). Layer 4 — UI talks only to 111d; **delivered:** 111d relays `/api/v1/chat`, `/chat/history`, `/agent/status`, `/agent/task` and republishes `/v1/agent/events` (Layer 4, 2026-10-13; translation table in `os/40-interface/README.md` §10). Layer 0 — KB dir is the release's `share/kb/` tree, already integrity-verified by 111d at boot.

**Known to Layer 4** (Layer 3 limitations found while building the relay, 2026-10-13; none blocks the relay):
- Proposals have no status or read-back upstream (no `/v1/proposals` route; files only). `111d` reads `<root>/agent/proposals/*.json` and owns decisions in `<root>/agent/decisions/`.
- Task-made proposals are journaled only as `task.done` (with `detail.proposal_id`); only the `proposal.write` tool journals `proposal.written`. `111d` covers both.
- Cancelling a chat (client disconnect) stops only at the next model round: the turn checks for a closed stream at the start of each round, so a round in flight runs to its end.
- `done.reply` is the final model round's text only; text from earlier tool rounds is streamed as `delta` but not repeated in `done`.
- Slow `/v1/agent/events` subscribers lose events silently (the broadcast channel holds 256; lag errors are dropped), which shows as gaps in `seq`. The replay on connect is the last 50.
- Test count drifted: `README.md:72` and the Summary above say 88; the suite is 93 now.
